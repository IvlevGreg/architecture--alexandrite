## Выбор подхода к мониторингу

Система поделена на группы по типам метрик:

1. Frontend приложения – Internet Shop, CRM, MES
2. Back приложения (взаимодействующие с очередью) – CRM API
3. Back приложения (без взаимодействия с очередью) – Shop API, MES API
4. Базы данных – Shop DB, MES db
5. Messages Queue 
6. S3


### Выбор подхода для групп метрик

Для всех частей приложения содержащих серверную часть необходим обязательно рассматривать USE, чтобы иметь возможность посмотреть на то как железо себя чувствует. Одним USE нельзя ограничиваться так как он не до конца отвечает на вопрос о текущем состоянии системы 

1. Тк в нашем случае Frontend приложения имеют только клиентскую часть, будем измерять метрики webVitals пользователей на реальных устройствах + мониторинга и отслеживания ошибок для приложений например Sentry
2. Back приложения (взаимодействующие с очередью)  - Red + USE
3. Back приложения (без взаимодействия с очередью) - Red + USE
4. Базы данных –  RED + USE
5. Messages Queue -  RED + USE
6. S3 - RED + USE
